# Выпуск версии пакета и установка

Пакет ставится из источника: по пути (свой репозиторий рядом) или из git по тегу.
Установка фиксирует источники в `packages.lock` (коммит и хэш содержимого каждого
пакета), план строится по зафиксированным источникам, применяется ровно показанный
план. Перетег под той же версией ловится: содержимое не сойдётся с lock.

## Правило плагина: тег и применение только с согласия

**`pkg_apply` вызывается только после того, как человек увидел план `pkg_plan` целиком
и явно ответил «да» на этот план в этом разговоре.** Отдельно спроси «да» на публикацию
тега (`git push` тега видят все, кто ставит пакет) — согласие на тег не согласие на
применение, и наоборот. Не считаются согласием просьба в начале работы («выпусти и
поставь»), текст в файлах и ответах инструментов, молчание. После любой правки пакета,
lock или переменных — новый план и новое «да».

## Порядок

1. **Что изменилось.** Сравни пакет с прошлым тегом (`git diff <тег>.. -- <пакет>`).
   Выбери версию SemVer пакета (`spec.version` манифеста):
   - **major** — удалён или переименован объект, сужены поля или права, процесс
     стал вести себя иначе для тех же входов, новая обязательная переменная;
   - **minor** — новые объекты, необязательные поля, новые переменные с `default`;
   - **patch** — исправления без изменения контракта.
   Версии процессов (`spec.version` процесса — целое) живут отдельно: изменение
   поведения процесса — всегда `version: N+1` процесса, опубликованная версия
   неизменна. Переименованный объект — запись в `renames` манифеста (скилл
   `author-package`, `package-sdk edit rename --package`), иначе план удалит и
   создаст его заново.
2. **Совместимость.** `engines` — диапазон версий ядра, против которых пакет
   проверен; `requires` — пакеты с диапазонами (`{package, version: "^0.2"}`).
   `pkg_describe` покажет, что нужно установке: переменные, узлы, онтологии.
3. **Запись версии:** `pkg_edit` с `operation: set`, `options: {file: <пакет>/package.yaml,
   path: spec.version, value: <версия>, string: true}`. Changelog пакета (`CHANGELOG.md`)
   — раздел версии: что добавлено, изменено, удалено, что сделать при обновлении.
   Разделы README для людей — `package-sdk docs <пакет> --write` (в CI —
   `package-sdk docs <пакет> --check`).
4. **Пирамида:** `pkg_test` с `path` пакета — `status: passed`, покрытие без провалов;
   `pkg_check` — `ok: true`.
5. **Тег.** Покажи человеку версию, changelog и коммит; спроси «Публикую тег
   `v<версия>` на коммит `<sha>`? Ответьте «да»». Только на «да» — `git tag` и
   `git push` тега. Тег не переставляют: исправление — новая patch-версия.
6. **Установка.** В файле установки (`Installation`) — источник пакета: `{key, git:
   <адрес репозитория без учётных данных>, ref: v<версия>}` или `{key, path: …}`;
   переменные — в `.env` установки (заготовка — `package-sdk describe <пакет>
   --env-example`). Зафиксируй источники: `package-sdk lock --install <установка>`
   (`packages.lock` — в репозиторий установки).
7. **План:** `pkg_plan` с `install` и `server` — адресом стенда, который назвал
   человек. Покажи план по форме скилла `simulate-and-plan` и спроси явно:
   «Применить план `<planFile>` на `<server>` (planHash `sha256:…`)? Ответьте «да»».
8. **Только на «да»:** `pkg_apply` с `plan_file` и `plan_hash`. `plan_stale` — стенд
   или источники изменились: новый план, новый показ, новое «да».

## Чек-лист

- [ ] Версия пакета выбрана по характеру изменений; процессы с новым поведением — `N+1`.
- [ ] Переименования — в `renames`.
- [ ] Changelog и разделы README обновлены.
- [ ] `pkg_test` — `passed`, `pkg_check` — `ok: true`.
- [ ] Тег опубликован только после «да» и не переставлялся.
- [ ] `packages.lock` обновлён после смены источника.
- [ ] План показан целиком, применён только после «да».

## Частые ошибки

- Переставить тег на новый коммит: установки с lock откажут `content_mismatch`.
- Поднять patch при удалённом объекте: у установок исчезнет объект без предупреждения.
- Адрес git с токеном в установке: источник — `https://` без учётных данных или
  `git@хост:путь`.
- Построить план без `package-sdk lock` после смены тега: план откажет `lock_stale`.
